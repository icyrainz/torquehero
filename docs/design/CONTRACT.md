# Foundation contract notes

Notes on the shared interfaces, written while the core modules were built. The code in `src/torquehero/{state,chart,game,config}.py` is authoritative; this file is the guided tour. Decisions are in `docs/SPEC.md` sections 8.7 to 8.9.

## Contract notes for sibling tasks (current as of 566bb10)
- Events (state.py): Judgement, Sound, FfbCue, Beat, SectionChange; each has a `kind` string ("judgement", "sound", "ffb", "beat", "section"). `GameEvent` is their union.
- Judgement: t, layer, note_kind, note_index, note_t, result, error, vel.
- Sound: t, layer, name, action (play/start/stop), vel, cause (hit/free/auto/miss), note_index, note_t (None for free play).
- AUDIO TIMING RULE: the audio engine schedules auto-layer sounds itself from the chart, sample-accurately, and IGNORES Sound events with cause="auto". The game still emits them for views and FFB. All other causes play on receipt.
- Sound.name is always a key of audio.oneshots (template filled with {gate} 1..6 or {side} "l"/"r", a note `sample`, "dud", "impact", or the riser loop name). For every layer with a trigger / gate-with-oneshot / riser entry in audio.layers, notes or not, validation requires what free play can emit: kick, hat, tom_l and tom_r, the riser loop and impact, dud when pads or fills have such an entry, plus every stab gate and sample the notes use. Only exception: free-play stabs on gates the chart never uses; the audio engine skips unknown names.
- Riser sounds: a pull during a riser note = start, cause "hit". The release that judges the riser = stop + impact with cause "hit" (or "miss" if judged miss) and note_index/note_t. Any other release (early, or after a forced judgement) = cause "free", no note.
- Sound.vel and Judgement.vel = `InputState.velocity.get(ctrl, 1.0)`.
- FfbCue: kick (dir -1/+1), rumble, riser_start, riser_release. Every riser_start is followed by exactly one riser_release (early release + re-pull gives two pairs). These are one-off markers: the FFB wind-up reads Snapshot.riser, which stays active (and `held` valid) from n.t until the riser is judged, up to drop + good_window (auto riser: until the drop).
- `Game.finished` = now > chart.length AND every note finalized (waits for the last good window and any forced riser release). The app stops on `finished`, not on now > length.
- InputState: analog fields (steer, steer_deg, brake, clutch, throttle, handbrake, lever0, lever1). One threshold, Config.press_threshold (0.5). `down` = every performance control past it now (buttons, gates, paddles AND held pedals/handbrake/levers); `pressed`/`released` = crossings this frame; steer never in these sets. `system` = system controls pressed this frame. `bound` = controls bound to a real device; `fallback` = controls served by keyboard/mouse (disjoint). `velocity` = {ctrl: 0..1} for each control in `pressed`; input.py owns the mapping (rise rate; key/button gives 1.0). `value(name)`, `gate` helpers.
- spin_mode "auto": net only when steer is in `bound`.
- `state.default_layer_modes(bound, fallback, needed=chart.controls_used())`: a layer is `you` only if every control it needs is in bound or fallback (without `needed`: all its controls); a layer the chart does not use is `you` if any of its controls is served; melody always you. `Chart.controls_used()` returns the SPEC 8.3 control names the notes need.
- Game applies `cfg.audio_offset` itself; `Snapshot.now` is the judge clock. `app.py` sets `game.phase` and fills `snapshot.ffb`.
- Snapshot beyond SPEC 8.4: `road_x`, `on_road`, `riser.held_frac`, `notes` (list of NoteView {index, done, result|None, progress|None} for notes from now-0.5 s to now+Config.lookahead; progress = spin rotation / 360, riser/expr/fader = time through note). The renderer pairs views with `chart.notes[index]`.
- `echo_target` = `chart.phrase_x(listen gates of the run, now)`: smoothstep between listen gates' x, reaching each x at its time; held at first x from one beat before. Validator checks the peak rate (ECHO_PEAK_FACTOR 1.5 x mean) and rejects two listen gates at one time with different x. `Chart.load/validate/from_dict` take `play_range_deg` and `echo_max_deg_s` (defaults 90, 180); the app passes Config values. echo_target is the goal: the FFB engine rate-limits toward it, including the step when a listen region opens.
- `Game.song_info()` -> SongInfo(title, artist, bpm, length, sections, layer_modes, layers_used).to_dict() for the companion timeline.
- `Snapshot.to_json()` never emits NaN/Infinity: non-finite floats become null.
- Config: only shared game tunables. Sibling modules persist their own settings in their own file under `config_dir()`.
- Fixtures: tests/fixtures/chart.json, snapshot.json; regenerate with `uv run python tests/fixtures/build.py` (test_fixtures fails on drift). `fixtures.build.audio_dict()` is the full manifest. Audio files named in it do not exist on disk; validation does not check files.
- CLI: `add_cli(sub)` must `set_defaults(func=handler)`; handler(args) returns exit code or None.
- `validate_dict` never raises; a note with any error is left out of cross-checks; template format errors are validation errors.
- stems extra: torch==2.11.0 and torchaudio==2.11.0 on every platform, from the cu128 index on Windows.
- Chart validation also: finite numbers only, t+dur <= length, bool fields are bools, sample is a non-empty string, fields foreign to a kind rejected, audio.layers entry required for every layer with notes, oneshot templates may use only {gate} and {side}.

## Readings chosen
1. Press matching: a press judges the earliest unfinished note in the good window that it matches. Only if none matches does a gate/paddle press count as a wrong press (miss + "dud") on the nearest unfinished note of its layer. Consequence: on a lone stab note, an early wrong gate inside the window is a miss, and the right gate after it is free play.
2. Free play outside any window plays the pressed gate's stab / side's tom (SPEC over demo).
3. `gate` audio mode fires its reinforcement one-shot on hits only; free play sounds only for `trigger` layers and the riser loop.
4. Riser: release accepted from drop - good_window to drop + good_window. An earlier release ends that wind-up (release cue) without judging; a re-pull starts a new one. Never released by drop + good_window = judged then, with a release cue if still held.
5. Long notes (spin/expr/fader/riser): the first frame at or after n.t counts no steering motion and only the time since n.t.
6. Starting a Game mid-song judges earlier unplayed notes as misses on the first frame (no seek support).


## Added after the wave-2 reviews
Every item is additive: existing names, fields and defaults are unchanged.
- Spin direction (SPEC 9 rule 10): `spin` notes accept optional `dir`, "cw" or "ccw" (`chart.SPIN_DIRS`; cw = `steer_deg` rising, to the right). `Note.dir` is None when absent, and then either direction counts. In net mode, turning against `dir` is a miss. Abs mode (keyboard/mouse) ignores `dir`.
- Turn offset: `Game.steer_offset_deg` is derived from the wheel, not counted: `360 x round(steer_deg / 360)`, clamped to -360..+360. It is re-derived only on the first update after construction or `reset()` and when a spin note is finalized (perfect, good or miss), never in between, so normal steering cannot flip it. In abs mode (steer not in `bound`) it is 0. A spin finalized with `|steer_deg|` above 540 (`game.SPIN_LOCK_DEG`) is a miss.
- Effective steering: `Game.steer_lane(inp)` is `inp.steer` while the offset is 0, else `(steer_deg - offset) / play_range_deg` clamped to -1..1. Gates, `on_road` and the perfect-hit FFB kick direction use it. `InputState` is unchanged.
- New Snapshot fields, appended at the end: `steer_offset_deg: float = 0.0`, `steer_lane: float = 0.0`, `steer_unwind: bool = False`, `steer_offset_changed: bool = False`. The FFB engine adds `steer_offset_deg` to every centre it commands. Views that draw the player's position use `steer_lane`. `steer_unwind` is true in net mode while `|steer_deg - steer_offset_deg| > 180`: the wheel and the offset disagree, views show a "turn back" hint and the FFB engine holds its springs off. `steer_offset_changed` is true on the frame the offset changed (a spin finalized) and on the first frame after construction or `reset()`; `steer_lane` may jump on that frame, so views should not animate or smooth across it.
- `chart.playability(chart_or_dict, difficulty="normal", cfg=None) -> list[str]`: every violation of SPEC 9 rules 1 to 11, each starting "rule N:" and naming note indices and times. It never raises. An invalid dict or an unknown difficulty gives one message. `validate_dict` does NOT call it, so existing charts keep loading. The CLI and generators call it explicitly. Readings: each tom is padded by `limb_travel` (a tom run is the union); rule 4: fader notes on lever 0 and lever 1 may not overlap, but one ending and the other starting at the same instant is allowed (the levers sit side by side and one hand can hold both); "target jump" = consecutive fader notes on the same lever, less than `limb_travel` apart, whose start differs from the previous end by more than `expr_perfect`; rule 5 uses `chart.FREE_HAND_JUMP` (0.4 lane units) and pads stabs and risers by `limb_travel`; rule 7 treats kicks within `limb_travel` of an expr note as left-foot kicks; rule 8 skips listen gates; rule 10 flags a spin with no `dir`, two turns the same way, and a song that ends off centre. Rule 3 and rule 11 margins are compared with 1 ms tolerance, so a margin of exactly `limb_travel` or one beat passes.
- Config: `limb_travel` 0.4 s and `max_lane_rate` {"easy": 1.0, "normal": 1.5, "hard": 2.5} lane units per second, gate to gate.
- Chart layer defaults: optional top-level `"defaults": {"layers": {layer: "you" | "auto"}}`, validated and exposed as `Chart.default_layers` (a dict, empty when absent; `to_dict` writes it only when it is not empty). `state.default_layer_modes(bound, fallback, needed, defaults=chart.default_layers)`: "auto" in defaults forces auto (melody too); "you" still becomes auto when the layer's controls are not served.
- Held means latched (SPEC 10, press and release): the game reads `"handbrake" in inp.down` for a pulled riser, in judging and in `Snapshot.riser.held`; it never compares the raw level to `press_threshold`. Test inputs that hold a control must put it in `down`.
- Config `wheel_range_deg` default is now 1080 (SPEC 9 rule 12; was 900).
- Allowed audio modes per layer (SPEC 8.9) are validation errors: `chart.ALLOWED_MODES`.
- `validate_dict` also returns an error string, not an exception, for a non-string `kind` (including lists and dicts), a non-string `stem`, and integers too large for a float (`_num` rejects them). A fuzz test covers random JSON-like input for `validate_dict` and `playability`.
- Fixture chart: identical up to 12 s; after that stab 12 and 13, fader lever 0 12-14 and lever 1 14.5-15.5, toms 16 and 16.5, spin cw 17.5 (dur 1.5), spin ccw 19.5 (dur 1.5), riser 21.5 (dur 2). Length is 24 s, with 48 beats. `playability()` returns [] on every difficulty. The sample snapshot carries the two new fields.
- Rebase note for siblings: the fixture chart is now 24 s long and its notes after 12 s moved (see above). On a conflict in `tests/fixtures/` or `tests/test_game.py`, take the base (foundation) version, then re-apply your own test additions. Spins without `dir` are still valid charts (`validate_dict` accepts them) but `playability()` reports rule 10 for them. Riser test inputs must put "handbrake" in `down` while pulled.
- Spin fixes (supersede the lines above where they differ): while a player spin is active (from its `t` until it is finalized), `steer_unwind` is false, `Snapshot.steer_lane` is `road_x` and so `on_road` is true. Gates are still judged on the real lane (`Game.steer_lane(inp)`); `road_x` is for the snapshot only. A spin is perfect, and finalized, on the first frame its rotation in the required direction reaches `spin_perfect_deg - spin_tolerance_deg` (new Config field, default 15); good and miss are still decided at the note end. The offset is re-derived on that frame from the spin's start angle plus one turn in its direction (`dir`, or the sign of the net rotation when absent), not by rounding the current angle, so a spin started far left still lands on +360. Good and miss re-derive from the current angle. `spin_tolerance_deg` is clamped to 0 .. `spin_perfect_deg - spin_good_deg`. A spin finalized with `|steer_deg|` at or above `Game.spin_lock_deg` = `min(540, wheel_range_deg / 2 - 5)` is a miss (535 with the default 1080 range). When spin mode leaves net mid-song (steer leaves `bound`) with a non-zero offset, the offset becomes 0 on that frame and `steer_offset_changed` is set. `Config.from_dict` merges a partial `max_lane_rate` over the defaults.
- One drawn road (SPEC 10): `Chart.blind_zones(good_window=0.12) -> [(start, end)]`. A blind run (consecutive blind gates) opens one beat before its first gate but never before the previous listen run closes (last listen gate + good_window), and closes good_window after its last gate. Its zone runs from the last road keyframe at or before the open to the first keyframe at or after the close (song end if none). `Chart.drawn_road()` pins every keyframe strictly inside a zone to x = 0; the zone's edge keyframes keep their x, so the blend in and out follows the `road_x` rule inside the edge intervals. `Chart.drawn_road_x(t)` and `chart.road_at(keys, t)` are public; `Game.drawn_road_x(t)` caches the keys with `cfg.good_window`. `Snapshot.road_x` is the drawn road, as are popup x and the kick direction; `on_road` is true everywhere inside a blind zone (`Game.in_blind_zone(t)`). Blind gates are judged at their real x. `Chart.road_x` is unchanged (the real road).
- New Snapshot field, appended: `steer_lane_jump: bool = False`, true on a frame where `Snapshot.steer_lane` may jump: `steer_offset_changed`, or a spin started or ended (steer_lane switched between `road_x` and the real lane). Views must not smooth across it. `steer_offset_changed` keeps its meaning (offset only).

## Added in the integration repairs
- Shared rules, one source each: `state.DIFFICULTIES` and `state.DIFFICULTY_LAYERS` (app and generate import them); `chart.ALLOWED_MODES` (audio imports it); `state.spin_in_progress(note, done, now)`: a spin is in progress from its `t` until it is finalized. `state.spin_running(snap, chart)` applies it to `Snapshot.notes`; `Game.spinning`, `render.turn_back_dir` and `ffb.spin_active` all use it. A NoteView with a progress is not enough: a spin ahead of `now` has progress 0.0.
- Difficulty (SPEC 10): the menu difficulty no longer deletes notes. Layers outside `DIFFICULTY_LAYERS[difficulty]` become "auto" in `defaults.layers` (the song plays their notes; `--layers` can still override). Easy still drops spins, listen and blind gates.
- `Game(chart, cfg, layer_modes, wheel_range_deg=None)`: the calibrated steer range (the steer binding's `range_deg`); `spin_lock_deg` = `min(540, range / 2 - 5)`. None or not positive uses `Config.wheel_range_deg`. The app passes the same value it gives `FfbEngine`.
- `FfbEngine.report()` adds `fps` (measured frames per second over 0.5 s, also while latched; None before the first frame) and `springs` ("measuring" before a frame time exists, "reduced" below 100 Hz, "off" below 50 Hz, else None; the rate floor, unchanged). `ffb.rate_text(report)` is the line the HUD and `--ffb-test` show; it adds LATCHED while `latched`.
- `--ffb-test` saves ffb_up / ffb_down gain changes only when started with `--ffb-gain` (`FfbTest(save_gain=)`); otherwise it logs that the tuned gain was kept. Without `--ffb-gain` it starts at `min(resolve_gain(...), 0.2)`.
- `play` opens its Window with `RenderSettings.load()`, and the Renderer draws with the Window's settings (the render preview does the same).
- `config.json`, `audio.json` and `render.json` load key by key (`config.load_settings`): an unreadable file gives the defaults, a bad key keeps its default, with one log warning either way (`ffb_gain` outside 0..1 and numbers too large for a float are bad values); `config.settings_fallback(obj)` is then true, and the first save copies the old file to `<name>.bad` (`config.backup_bad`; the marker clears only after the copy succeeds, and a failed copy fails the save). After a config fallback, `app.load_config` caps `ffb_gain` at FIRST_RUN_GAIN (0.2) for the session and any save, whatever `ffb_first_run_done` says.
- `start_companion(host, port)` saves a given host to `companion.json` once the server listens; the port is for that run only. `CompanionServer.start_line()` is the start-up line.
